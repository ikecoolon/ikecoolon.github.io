# 宠物健康报告完整业务设计

> 状态：业务访谈已完成；仍需甲方确认的事项单独列出，不能提前作为实现要求。

## 1. 产品目标

客户在线下门店为宠物完成检测，检测机构出具 Excel。平台运营人员将 Excel 导入、处理异常、补充内容、执行分析规则、人工审核并发布；用户登录小程序后领取或查看自己宠物的最新报告。

报告同时提供专业检测数据和通俗解释，并可以把健康建议关联到现有商城商品。商城继续负责商品、规格、价格、库存和交易，报告平台只负责健康语义和推荐关系。

## 2. 首期范围

### 包含

- 已知 Excel 模板的单份和多文件批量导入。
- 原始文件、原始检测事实、有效检测结果和报告呈现内容的分层追溯。
- 用户、运营建档宠物、报告归属、领取码和归属纠错。
- 参考范围、菌群分类、科普内容、分析规则和人工审核。
- 报告发布、更正、作废及后台历史版本。
- 小程序宠物入口、报告入口、领取报告和最新发布报告查看。
- 健康需求标签、主推 SPU、候选商品及商城实时状态联动。
- 可重复演示完整流程的 Mock 数据。

### 不包含

- 通用角色权限、系统审计和平台治理能力。
- 家庭成员授权、多人共享或用户自行转移报告。
- 用户在小程序新增、编辑、纠错或合并宠物。
- 购物车、订单、支付、商品点击或交易转化归因。
- 发布通知、订阅消息和线下通知任务。
- 跨报告趋势分析、最终报告 PDF 或 Word 导出。
- 小程序中的报告旧版本查看。
- 用户端统一健康免责声明。
- 机构合同、联系人、结算或机构账号管理。

## 3. 业务参与方

| 参与方 | 业务责任 |
| --- | --- |
| 小程序用户 | 登录、扫码或输入领取码、确认领取、查看自己的宠物与报告 |
| 运营人员 | 批量导入、线下确认客户、创建宠物、处理异常、补录和维护报告 |
| 审核人员 | 核对专业数据和呈现内容、调整综合评定与建议、确认发布检查并发布 |
| 检测机构 | 在线下完成检测并交付符合已知结构的 Excel |
| 商城 | 提供 SPU、SKU、分类、价格、库存、上下架状态、商品详情和交易能力 |

运营人员和审核人员表示业务职责，不在本项目中重新设计角色权限体系。

## 4. 完整业务流程

1. 运营一次选择一个或多个 Excel，每个文件对应一只宠物的一次检测。
2. 平台逐文件识别已知模板、来源机构标识、外部报告编号或样本编号，并执行重复检查。
3. 关键异常导致该文件导入失败；局部异常保留已解析内容并形成待办标记。
4. 解析成功后生成平台报告编号和待归属报告，原始 Excel 永久保留。
5. 运营通过电话或微信确认客户，选择已有宠物或在后台创建宠物，并完成报告归档。
6. 已注册用户可以由运营直接绑定；其他情况生成一次性领取码或二维码。
7. 运营处理未知检测项、单位异常和缺失值，确定有效检测结果与有效参考范围。
8. 平台生成规则分析草稿；审核人员检查命中依据、组合结论、解释、建议和健康需求标签。
9. 审核人员填写人工综合分、A–E 等级、人工比较百分位和平台评估维度，必要时修改报告物种、专业数据或呈现文案。
10. 审核人员配置推荐项及主推 SPU，执行固定发布检查后发布。
11. 已绑定或已领取用户可以查看报告；未领取报告可以先发布，用户领取后立即可见。
12. 已发布报告需要修正时创建更正草稿，旧版本继续向用户展示；新版本重新审核发布后一次性替换。
13. 无效报告通过作废终止并从小程序消失，管理端继续保留全部追溯资料。

## 5. 状态与可见性

### 管理端主状态

| 状态 | 含义 | 可进入状态 |
| --- | --- | --- |
| 待归属 | 已解析，但尚未完成宠物建档和报告归档 | 待完善、已作废 |
| 待完善 | 已归入宠物，正在处理数据、分析和呈现内容 | 待审核、已作废 |
| 待审核 | 等待最终核对和发布检查 | 已发布、待完善、已作废 |
| 已发布 | 存在当前面向用户的发布版本 | 更正草稿、已作废 |
| 已作废 | 报告离开正常流程的终止状态 | 无正常后续状态 |

待确认检测项、缺失值、单位异常、待重新分析和推荐商品失效等均为待办标记，不扩张为新的主状态。

### 用户状态投影

| 后台情况 | 用户是否可见 | 用户看到的状态或行为 |
| --- | --- | --- |
| 已直接绑定或已领取，但尚未发布 | 是 | “进行中”不可点击卡片 |
| 已发布且已绑定或已领取 | 是 | “已发布”，可进入最新版本 |
| 已发布但尚未领取 | 否 | 领取后立即显示为“已发布” |
| 导入失败、待归属但未绑定、已作废 | 否 | 不展示 |

## 6. Excel 导入与异常处理

### 文件与模板

- 一个 Excel 只表示一只宠物的一次检测。
- 批量上传中的各文件独立成功或失败，不互相回滚。
- 平台只解释已经通过产品开发支持的已知模板，不提供运营现场字段映射。
- 新机构或新版文件结构允许通过后续程序开发增加支持，适配完成后直接可用，不设置运营模板测试、启用或停用流程。
- 报告保存来源机构名称文本；已知模板另提供稳定的来源机构标识，用于模板识别和重复判定，不建立机构管理资料。

### 重复判定

同一来源机构标识下，外部报告编号或样本编号相同即视为重复并禁止再次导入。即使后续文件内容不同，也不覆盖原始文件、不创建新报告；差异由运营在原报告内进行可追溯人工修订。

### 异常分级

| 异常类型 | 示例 | 处理 |
| --- | --- | --- |
| 关键导入异常 | 未知模板、文件损坏、缺少报告唯一标识 | 整份失败，不创建报告草稿 |
| 局部导入异常 | 未知检测项、异常数值格式、单位不匹配、局部字段缺失 | 保留已解析数据，报告进入待处理异常 |

已知模板中出现新指标或新菌群时，保留 Excel 原始名称并标记待确认；运营可以关联已有项目，或确认后新增平台正式检测项。

## 7. 检测结果与参考范围

### 三层数据

1. 原始检测文件和原始检测事实不可覆盖。
2. 有效检测结果用于分析，可以沿用原始值，也可以来自人工补录或可追溯修订。
3. 报告呈现内容面向用户，包括等级、解释、建议、推荐及模块组织。

### 检测分类

- 普通检测指标与菌群分类资料分别维护。
- 菌群采用通用分类树，支持门、纲、目、科、属、种等层级；当前报告重点使用门和属。
- 报告物种来自 Excel，审核人员可以修正。修正会重新匹配称谓、参考范围、规则、本次结果解释和推荐适用性，但不会改写跨报告复用的中性科普，也不自动修改宠物档案物种。

### 单位与范围

- 每个检测项采用标准检测单位。
- 已知模板只能执行明确约定的单位换算，不能根据数值猜测。
- 系统默认选取顺序：Excel 导入范围 → 匹配的平台参考范围方案 → 空；审核人员显式修订时可以覆盖默认结果，但必须保留原值和修改原因。
- 参考范围方案由专业人员按检测方案成套导入或维护，至少记录专业依据、适用物种、检测方案和单位；运营人员不按“物种 × 指标”逐项创建范围。
- 一个方案可以同时勾选多个经专业确认共用范围的物种；新增物种默认不继承，可复制现有方案形成独立版本，或直接批量导入检测机构提供的整套范围。
- 平台范围只在检测项或菌群、报告物种、检测方案及单位均匹配时兜底；不预建年龄、品种、饮食、地区等没有来源依据的空分层。
- 有效参考范围随报告版本固化，平台配置变化不重算历史发布报告。
- 同时存在正常范围与理想目标时，暂按“正常范围判断状态、理想目标只作参考”处理，最终仍需甲方确认。

### 特殊结果

- 未决缺失允许保留和发布，不参与异常判断和商品推荐。
- 实验室明确的未检出是有效状态，不等于 0 或缺失；只有明确适用于未检出的规则才能解释。
- 有检测值但无有效参考范围时，用户可看检测值和“暂无参考范围”，不展示正常、偏高或偏低，也不执行依赖范围的规则。

## 8. 分析规则与报告内容

### 规则能力

- 分析规则具有草稿、启用、停用和版本。
- 支持“全部满足”和“任一满足”的条件组合，以及数值范围、未检出、报告物种和其他检测结果。
- 缺失只能用于跳过判断或产生中性完整性提示，不能据此生成健康风险、健康建议或商品推荐。
- 不向运营开放任意脚本公式。
- 新规则只用于之后生成或主动重新分析的报告，不自动改变已发布报告。

### 规则输出与组合

- 规则可以生成专业发现、通俗解释、健康建议、风险级别和健康需求标签。
- 同一检测项命中多条规则时，以风险级别和优先级确定主结论，合并兼容补充内容，并通过冲突分组排除互斥结果。
- 指向同一健康需求标签的多条专业发现合并为一个推荐项，但保留全部检测依据。
- 原始规则命中、组合结果和审核后的最终文案都要保留。
- 审核人员可以排除规则结果、补充人工专业发现或微调解释，但不能抹除原始命中记录。

### 人工内容

当前由审核人员人工确定且彼此独立：

- 人工综合分；
- A–E 人工评定等级；
- 人工比较百分位；
- 情绪、免疫等平台评估维度。

综合分与等级不做对应关系校验。等级只控制固定主题：A 雨林、B 森林、C 草原、D 苔藓、E 沙漠。报告中的动物称谓根据报告物种匹配，审核人员可以修正。

### 科普与素材

- 平台统一维护分类层级科普和菌群科普模板。
- “莎莎的雨林中，药草与苔藓（放线菌门）——略显繁茂”由报告宠物昵称、等级主题、菌群场景短称、菌群名称和相对范围状态词组合，用户端呈现为一条连贯文案。
- 菌群科普只维护设计图实际使用的可选场景短称和一段跨报告中性说明，不为每个门或属复制宠物名、主题或完整句式。
- “略显稀疏 / 生机适宜 / 略显繁茂”等状态词按检测值相对有效参考范围的偏低、正常、偏高状态全局配置；没有有效范围时不追加状态词。状态词只是场景修辞，不替代分析规则生成的专业解释。
- 偏高、偏低、未检出等状态解释，以及当前宠物的影响和健康建议，由物种与结果相关的分析规则生成并进入单份报告审核，不从菌群科普模板兜底。
- “某菌门包含哪些菌属”由分类树关系得到，不重复人工维护名单。
- 审核人员只能覆盖单份报告的通俗解释、本次分析和健康建议，不能在审核报告时修改平台菌群身份和分类关系。
- 等级背景和品牌装饰可以全局更新；直接承载专业含义的图片随报告版本固化。

## 9. 审核、发布、更正与作废

### 审核修改范围

审核人员可修改有效检测结果、有效参考范围、报告物种、综合评定、解释、建议和推荐项。修改专业数据时保留修改前后内容和原因，并要求重新确认规则分析。

### 固定发布检查

阻断发布：

- 尚未完成宠物建档和报告归档；
- 原始来源不可追溯；
- 报告物种未确定；
- 人工等级或综合分未填写；
- 没有任何有效检测结果；
- 任一必备预设报告模块完全没有可展示内容。

只警告、允许确认发布：

- 单项未决缺失；
- 某项参考范围、解释或建议为空；
- 推荐商品失效或没有候选商品。

绑定平台用户或完成用户领取不阻断发布。各报告类型的必备模块和最低非空标准仍需甲方确认。

### 更正与作废

- 已发布报告修改时创建更正草稿，用户继续查看旧发布版本。
- 新版本审核发布后替换当前版本；用户只看到最新版本和最近更新时间，不看版本号、旧内容或变更摘要。
- 旧版本仅管理端可追溯。
- 报告作废后立即从用户端消失，但原始文件、版本和操作记录保留。
- 报告绑错用户或宠物时允许直接改绑并立即生效，原用户随即失去访问；管理端保留更正前后归属、操作人员、时间和原因。

## 10. 用户、宠物与报告领取

- 宠物统一由运营根据电话或微信确认结果在后台创建和维护。
- 小程序宠物资料完全只读，不提供新增、编辑、纠错申请、重复判断或合并。
- 已注册用户可由运营通过手机号搜索并人工核对，但最终绑定平台用户账号，Excel 手机号不自动决定归属。
- 未注册客户可以先形成待认领宠物和报告。
- 领取码不设固定有效期，只能成功领取一次；运营可在领取前作废并重新生成。
- 用户从固定“领取报告”入口扫码或手动输入领取码。
- 领取前只确认宠物名称、检测项目和检测日期；不能重新选择宠物或修改资料。
- 已领取或已作废的码统一提示失效并引导联系门店或运营，不暴露归属用户信息。

## 11. 小程序业务范围

### “我的”页面

- 宠物入口：显示宠物数量、宠物列表和每只宠物的独立报告数量。
- 报告入口：跨宠物平铺报告，按检测日期降序，支持“已发布”和“进行中”过滤。
- 领取报告入口：支持扫码和手动输入领取码。

报告卡片只展示宠物名称、报告名称或检测项目、检测日期和状态。进行中卡片不可点击；已发布卡片进入报告概览。

小程序默认首页是“我的”还是最新已发布报告，仍需甲方确认。

### 报告查看

- 首屏为综合概览：宠物称谓、等级、综合分、人工百分位、核心指标和等级主题。
- 专业内容只展示本次实际涉及的分类和检测项。
- 菌门详情可以继续查看检测值、范围、所含菌属、分析和建议。
- 同一检测项同时提供专业数值、参考范围、通俗解释、本次分析和健康建议，不拆成两套完整报告。
- 未检出明确显示“未检出”；缺失项不显示数值，固定位置必要时显示“暂无有效结果”。
- 任一预设模块完全为空会阻断发布，因此用户不会看到完整空模块。
- 用户只能查看当前发布版本，不看后台报告版本历史。
- 不提供跨多次检测的趋势图；设计图中的理想菌群对比属于单份报告内部对比。
- 平台不发送发布通知，也不展示统一健康免责声明。

## 12. 健康建议与商城联动

### 推荐模型

每个推荐项最多包含：

- 一个运营指定的主推 SPU；
- 一个或多个报告领域维护的健康需求标签；
- 支撑该建议的专业发现和推荐理由。

一个健康需求标签可以映射多个 SPU，并维护推荐顺序、适用物种和启用状态。报告不把商城分类直接当作健康标签，也不把商城分类下全部商品自动纳入候选。

报告发布时固化专业发现、推荐理由、健康需求标签、主推 SPU 和规则版本；商品名称、价格、库存、上下架状态等商城事实在用户查看时读取当前值。

### 商品状态处理

| 商城状态 | 报告行为 |
| --- | --- |
| 主推 SPU 正常上架且可购 | 展示主推商品 |
| 主推 SPU 上架但库存为 0 | 保留专业推荐关系，并提供标签候选商品 |
| 主推 SPU 不存在、回收或下架 | 不展示直接目标，改用健康需求标签解析候选商品 |
| 没有任何可用候选商品 | 仍完整展示健康建议，不出现空白商品区域 |

用户选择商品后直接进入现有商城 SPU 详情并自行选择 SKU。报告模块不复制商品详情，不处理购物车、订单或支付，也不记录商品点击。

### 是否需要修改现有商城

根据已核对的 `rondo-module-mall` 现有能力，报告联动可以在不修改商城模块源码的前提下完成：

- 商城已经提供 SPU 查询、批量查询、有效性校验和商品详情能力；
- SKU、价格、库存和上下架状态继续由商城负责；
- 报告领域自行维护健康需求标签、标签与 SPU 的映射、主推 SPU 和候选解析；
- 报告模块保存商城 SPU 标识并使用现有商城能力取得实时商品事实。

如果未来要求按报告来源追踪加购、订单和支付，才需要另行设计归因链路；当前明确不做。

商品推荐在小程序中的具体位置、卡片形式、候选数量和排序仍需甲方确认。

## 13. 管理端功能清单

管理端登录后直接进入报告中心，不设置业务首页。

### 报告中心

- 全部、待归属、待完善、待审核、已发布和已作废视图。
- 按平台报告编号、外部报告编号、样本编号、手机号、宠物名称、物种、来源机构名称、状态、检测日期和待办标记查询。
- 单份报告按来源与归属、有效结果、综合评定、分析解释、健康建议与商品推荐、发布检查、版本和操作记录组织。
- 只允许逐份执行归属、专业修改、审核、发布和作废。

### Excel 导入

- 多文件批量上传。
- 批次及逐文件成功、失败和异常结果。
- 失败原因和失败文件重新上传。
- 原始 Excel 查看与下载。

### 用户与宠物

- 查询平台用户并辅助手机号核对。
- 后台创建和编辑宠物。
- 查看用户的宠物数量、宠物名下报告数量及报告列表。
- 生成、作废和重新生成领取码。
- 直接绑定和归属纠错。

### 专业配置

- 普通检测指标。
- 菌群分类树、分类层级科普和菌群科普模板。
- 平台参考范围。
- 分析规则版本、条件、输出、优先级和冲突分组。
- 健康需求标签、标签商品映射和无效商品提示。

### 明确不做

- 管理端业务首页和经营分析看板。
- 机构资料与 Excel 模板配置页面。
- 批量归属、批量审核和批量发布。
- 会员、积分、消费、回访和客户营销。
- 最终报告 PDF 或 Word 导出。

## 14. Mock 演示场景

演示数据至少覆盖：

1. 多文件批量导入：正常文件、重复文件、局部异常和关键失败。
2. 待归属报告完成用户确认、宠物建档和领取码生成。
3. 用户扫码及手动输入领取码，确认后看到进行中报告。
4. 运营补录缺失值、处理新检测项、确定范围并重新生成规则分析。
5. 审核人员填写综合评定、微调解释、配置主推商品并发布。
6. 用户通过宠物入口和报告入口查看最新已发布报告。
7. 已发布报告创建更正草稿，旧版本继续可见，新版本发布后替换。
8. 主推商品下架后自动使用健康需求标签取得候选商品。
9. 报告直接改绑到正确用户或宠物，并在后台查看纠错记录。
10. 报告作废后从小程序消失但后台仍可追溯。

## 15. MVP 验收标准

- 已知 Excel 模板可批量导入，每个文件独立处理，原始文件可追溯。
- 重复报告、关键异常、局部异常和待确认检测项符合既定规则。
- 原始事实、有效结果、规则命中、审核内容和发布版本之间边界清晰。
- 运营能够完成归属、宠物建档、补录、审核、发布、更正、作废和纠错。
- 用户能够领取报告，并通过宠物或报告入口查看最新发布版本。
- 进行中报告不可进入，旧版本、失败报告和作废报告不向用户展示。
- 主推 SPU、健康需求标签和候选商品能按商城实时状态正确降级。
- 不修改现有商城模块即可完成商品详情承接。
- 所有代表流程均有稳定 Mock 数据，能够重复演示且不依赖真实机构、真实微信用户或真实订单。

## 17. 现有原型需要校正的业务点

- 小程序不能向用户展示报告旧版本或“查看此版本”入口，用户始终只看当前发布版本。
- 小程序宠物资料应只读，不能新增或编辑。
- 小程序需要落实宠物、报告和领取报告三个入口，但默认首页暂不确定。
- 进行中报告只显示不可点击卡片，不进入进度详情。
- 管理端不需要业务首页，日常工作从报告中心开始。
- 报告状态、待办标记、归属、规则命中、版本和商品降级必须由同一套 Mock 数据贯通，不能继续由页面各自维护孤立数据。
