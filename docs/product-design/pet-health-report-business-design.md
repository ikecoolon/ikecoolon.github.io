# 宠物健康报告完整业务设计

> 状态：业务访谈已完成。第 0 节已内部决定（含原 Q10 及“同一商城小程序内二次开发”的实施方式），本文不得与之矛盾；第 1 节 Q1–Q6 为实验室读数阻塞项；第 2 节 C1–C4 已闭环、不挡出报告；第 3 节 Q7–Q9、Q11–Q12 为体验与规则。未拍板的不能提前作为实现要求。

## 1. 产品目标

客户在线下门店为宠物完成检测，检测机构出具 Excel。平台运营人员先确认或创建用户、在登记送检时创建并关联宠物，再从该送检记录导入 Excel、处理异常、补充内容、执行分析规则、人工审核并发布；用户登录小程序后只读查看自己的宠物和已发布报告。

报告同时提供专业检测数据和通俗解释，分析、建议与商品推荐按菌门组织，并允许运营在每个菌门的建议下直接关联现有商城商品。宠物健康报告在现有商城小程序同一 AppID 内二次开发，复用商城已有登录态、商品详情、购物车、订单、支付和退款能力；商城继续负责商品、规格、价格、库存和交易，报告平台只保存运营人工选择的商品关联和展示顺序。

## 2. 首期范围

平台当前及长期只支持宠物微生物组报告，不建设可配置报告类型、不预留多报告类型配置入口，也不把当前设计抽象成通用报告引擎。

### 包含

- 从已登记送检记录导入已知 Excel 模板：单文件挂到该记录；多文件仅作为 N 条待导入送检记录由人配对 N 个文件。不做无预登记批量导入。
- 原始文件、原始检测事实、有效检测结果和报告呈现内容的分层追溯。
- 用户、运营建档宠物（在登记送检时创建）、报告与宠物关联、宠物与用户关联及关联纠错。
- 参考范围、菌群分类、科普内容、分析规则和人工审核。
- 报告发布、更正、作废及后台历史版本。
- 现有商城小程序内新增健康报告入口、页面与路由；健康报告模块首页作为当前宠物入口：处理中占位、最新已发布报告入口，以及该宠物历史已发布报告的同一份列表。
- 运营人工选择的主推 SPU、可选关联推荐 SPU 及商城实时状态联动；可购商品在同一小程序内进入既有商城商品详情。
- 可重复演示完整流程的 Mock 数据。

### 不包含

- 通用角色权限、系统审计和平台治理能力。
- 家庭成员授权、多人共享或用户自行转移报告。
- 用户在小程序新增、编辑、纠错或合并宠物。
- 用户侧完整宠物列表页、宠物 tab，以及把报告做成「概览 / 对比 / 菌门」三个 tab。
- 新建或重做购物车、订单、支付和退款后端；健康报告模块复用商城现有交易能力。商品点击或交易转化归因仍不包含。
- 发布通知、订阅消息和线下通知任务。
- 跨报告趋势分析、最终报告 PDF 或 Word 导出。
- 小程序中的报告旧版本查看。
- 用户端统一健康免责声明。
- 机构合同、联系人、结算或机构账号管理。

## 3. 业务参与方

| 参与方 | 业务责任 |
| --- | --- |
| 小程序用户 | 登录并只读查看自己的宠物与已发布报告；资料有误时线下联系运营或客服 |
| 运营人员 | 登记送检、从送检记录导入结果、处理异常、补录和完善报告；纠错（改归宠物 / 换用户） |
| 审核人员 | 核对专业数据和呈现内容、调整综合评定与建议、确认发布检查并发布 |
| 检测机构 | 在线下完成检测并交付符合已知结构的 Excel |
| 商城 | 提供 SPU、SKU、分类、价格、库存、上下架状态、商品详情和交易能力 |

运营人员和审核人员表示业务职责，不在本项目中重新设计角色权限体系。

## 4. 完整业务流程

0. 运营确认或创建平台用户。
1. 运营创建宠物并关联该用户，随即登记送检：填写样本编号（可从试管标签或微信补填，不要求出现在 Excel 中，也不用于自动匹配文件）、送检日期和检测机构，生成待导入结果送检记录。宠物是履约对象，不是空档案。用户端随即看到不可点击「报告处理中」。
2. 运营在送检管理中从该送检记录发起「导入结果」，挂上一份 Excel；成功后复用该送检记录、写入检测结果并生成唯一报告草稿，进入待完善。关键失败保留原记录为待导入结果，重新导入同样从该送检记录发起。
3. 多文件导入只允许把 N 份 Excel 分别挂到 N 条待导入送检记录，由人配对；不做「无预登记批量导入」，不创建没有送检记录的报告，主路径不进入待归属。
4. 平台逐文件识别已知模板与来源机构标识，并依据送检记录侧编号做重复检查。Excel 表内没有身份字段；文件名只是人工提示，不用于自动匹配。
5. 关键异常导致该文件导入失败且不新建送检记录或报告；局部异常保留已解析内容，并在报告工作台形成「缺失未处理」等待办角标。
6. 解析成功后进入待完善（宠物已存在），再经待审核、已发布；用户端在发布前始终只见「报告处理中」。模型仍保留待归属，但不是 v1 入口。
7. 报告归错宠物或宠物关联错用户时，运营走纠错（改归宠物 / 换用户），不作为主路径建档步骤。
8. 运营在工作台检测结果模块处理未知检测项、单位异常和缺失值，对照 Excel 原始值修改或补录有效值并填写原因，确定有效检测结果与有效参考范围。
9. 平台按菌门生成分析单元：每个有结果的菌门得到规则命中列表、「分析」草稿和「建议」草稿；审核人员逐菌门检查命中依据、排除或改写并单独确认。
10. 审核人员填写人工综合分、A–E 等级、人工比较百分位和平台评估维度，必要时修改报告物种、专业数据或呈现文案。
11. 运营人员在需要商品承接的菌门分析单元中选择主推 SPU 和可选关联推荐 SPU，审核人员执行固定发布检查后审核并直接发布。
12. 报告发布后，宠物当前关联用户可点击查看完整报告；同一业务项不再重复显示处理中占位。
13. 已发布报告需要修正时，从工作台顶栏或报告中心「更多」创建更正草稿，旧版本继续向用户展示；新版本重新审核发布后一次性替换。
14. 无效报告从工作台顶栏或报告中心「更多」作废终止并从小程序消失，管理端继续保留全部追溯资料。

## 5. 状态与可见性

### 管理端主状态

报告只有一个主状态字段，取值五种；另有布尔字段「更正草稿进行中」和文本字段「退回原因」。

| 状态 | 含义 | 可进入状态 |
| --- | --- | --- |
| 待归属 | 模型保留：已解析但尚未完成宠物建档和报告归档。v1 主路径不进入、也不是入口 | 待完善、已作废 |
| 待完善 | 已归入宠物，正在处理数据、分析和呈现内容；审核退回后回到此状态并显示退回原因 | 待审核、已作废 |
| 待审核 | 等待最终核对和发布检查 | 已发布、待完善、已作废 |
| 已发布 | 存在当前面向用户的发布版本；创建更正草稿后主状态不变，仅置「更正草稿进行中」 | 已作废 |
| 已作废 | 报告离开正常流程的终止状态 | 无正常后续状态 |

- 不设「审核退回」「已通过」「已更正」状态，也不设任何与「领取」相关的状态；审核退回表达为待完善加退回原因，审核通过后直接发布。
- v1 成功导入后进入待完善；待归属留在状态模型中，但不是入口，报告中心「待处理」只聚合待完善与待审核。
- 待办标记只保留待重新分析、缺失未处理、商品失效、未关联用户四类，仅在报告工作台作为角标出现，报告中心列表不显示也不提供待办筛选。
- 待确认检测项、单位异常等其他报告处理问题不扩张为新的主状态，在单份报告工作台的对应模块及发布检查中呈现。

### 用户可见性

| 后台情况 | 用户是否可见 | 用户看到的状态或行为 |
| --- | --- | --- |
| 宠物已关联当前用户，报告已发布且未作废 | 是 | 在宠物历史报告中直接查看当前发布版本 |
| 宠物已关联当前用户，已登记送检或报告未发布 | 是 | 不可点击的「报告处理中」，不暴露内部状态 |
| 宠物未关联当前用户 | 否 | 不展示 |
| 导入失败、已作废 | 否 | 不展示 |

## 6. Excel 导入与异常处理

### 文件与模板

- 一个 Excel 只表示一只宠物的一次检测。
- 多文件导入只允许运营把 N 份 Excel 分别挂到 N 条待导入送检记录；各文件独立成功或失败，不互相回滚。从未登记送检的文件不能导入，也不能创建报告。
- 平台只解释已经通过产品开发支持的已知模板，不提供运营现场字段映射。
- 新机构或新版文件结构允许通过后续程序开发增加支持，适配完成后直接可用，不设置运营模板测试、启用或停用流程。
- 报告保存来源机构名称文本；已知模板另提供稳定的来源机构标识，用于模板识别和重复判定，不建立机构管理资料。

### 真实文件结构

已核对的三份真实报告（`docs/product-design/report/*.xlsx`）结构一致：单 sheet，九列（superkingdom、phylum、class、order、family、genus、species、`Your sample (%)`、`vs AVG notice`）；只有属级行，同一属 1–13 行；class / order / family 全部为占位值；没有菌门值、参考范围、Alpha 多样性 / 均匀度 / 丰富度，也没有宠物、样本、报告编号或日期。`vs AVG notice` 只有 `high` / `low` / `-`，三份文件的占比合计分别为 100.01%、120.80%、134.97%。文件配对已决定：导入只从送检记录发起，把一份 Excel 挂到该记录上；文件名只是人工提示。同属多行如何合并、属级如何聚合为菌门值、合计偏离 100% 的含义，见 [开放问题清单](./open-questions.md) Q1–Q3；在此之前原型只用 Mock 数据演示。

### 重复判定

同一来源机构标识下，送检记录侧的外部报告编号或样本编号相同即视为重复并禁止再次导入。即使后续文件内容不同，也不覆盖原始文件、不创建新报告；差异由运营在原报告内修改当前有效结果，原始文件和首次解析事实继续保留。真实 Excel 表内不含编号或身份，重复判定不从 Excel 表内读身份。机构以后会否在文件名或表内提供标识，只影响导入是否更省事（Q11），不改变「先登记再挂文件」。

### 异常分级

| 异常类型 | 示例 | 处理 |
| --- | --- | --- |
| 关键导入异常 | 未知模板、文件损坏、未从送检记录发起导入 | 整份失败，不创建报告草稿 |
| 局部导入异常 | 未知检测项、异常数值格式、单位不匹配、局部字段缺失 | 保留已解析数据，在报告工作台形成待处理问题 |

已知模板中出现新指标或新菌群时，保留 Excel 原始名称并标记待确认；运营可以关联已有项目，或确认后新增平台正式检测项。

## 7. 检测结果与参考范围

### 三层数据

1. 原始检测文件和原始检测事实不可覆盖。
2. 有效检测结果用于分析，可以沿用原始值，也可以来自人工补录或修订；只保存当前有效值、人工来源和当前修改原因，不保存逐次值变更链，原始事实继续保留。
3. 报告呈现内容面向用户，包括等级、各菌门的分析与建议、商品推荐及模块组织。

### 检测分类

- 普通检测指标与菌群分类资料分别维护。
- 菌群采用通用分类树，支持门、纲、目、科、属、种等层级；当前报告重点使用门和属。
- 原始菌群记录是属级行，菌门值只能由属级聚合得到，聚合口径待甲方确认（Q1–Q3）。
- 报告物种来自 Excel，审核人员可以修正。修正会重新匹配称谓、参考范围、规则和本次结果解释，并提示运营重新检查各菌门已人工选择的商品是否合适；系统不会自动替换商品，也不会改写跨报告复用的中性科普或宠物档案物种。

### 单位与范围

- 每个检测项采用标准检测单位。
- 已知模板只能执行明确约定的单位换算，不能根据数值猜测。
- 系统选取顺序：审核人员确认可用的 Excel 导入范围 → 匹配的平台参考范围方案 → 空。v1 真实 Excel 不含导入范围，平台范围方案是后续增强，因此空是当前可发布路径，不是阻断。系统不校验导入范围的专业有效性，也不允许在单份报告中手填第三套范围。
- 三份真实 Excel 均不含参考范围。没有任何有效参考范围时仍可发布：对比模块隐藏，菌门 / 菌属卡不显示范围，也不拼「略显稀疏 / 生机适宜 / 略显繁茂」。设计稿中的 2%–8%、12%–20%、15%–30%、40%–65% 不得进入生产。不允许在单份报告里手填第三套范围。平台范围方案是后续增强，不是出报告的前提。机构以后会否另给整套范围见 [开放问题清单](./open-questions.md) C1，不挡 v1。
- 参考范围方案由专业人员按检测方案成套导入或维护，记录适用物种、检测方案、单位以及各项正常下限和正常上限；不增加参考依据说明、单侧范围或理想目标字段，运营人员不按“物种 × 指标”逐项创建范围。
- 一个方案可以同时勾选多个经专业确认共用范围的物种；新增物种默认不继承，可复制现有方案形成独立版本，或直接批量导入检测机构提供的整套范围。
- 平台范围只在检测项或菌群、报告物种、检测方案及单位均匹配时兜底；不预建年龄、品种、饮食、地区等没有来源依据的空分层。
- 未发布工作版本每次打开时自动采用最新匹配的平台范围，工作台检测结果模块对每条结果显示“报告导入”“平台配置”或“无有效范围”来源；平台范围同时显示方案名称和版本。范围发生变化时标记相关菌门需要重新分析，不静默覆盖人工分析与建议。
- 有效参考范围随报告版本固化，平台配置变化不重算历史发布报告。
- 对比与状态判断只使用正常下限和正常上限，图表坐标起点不等同于真实下限；平台不维护独立理想目标值。

### 特殊结果

- 未决缺失允许保留和发布，不参与异常判断和商品推荐。
- 实验室明确的未检出是有效状态，不等于 0 或缺失；只有明确适用于未检出的规则才能解释。
- `vs AVG notice` 为 `high` / `low` 的记录，其实验室比较状态直接作为规则条件；为 `-` 的记录仍是有效检测结果并正常展示，实验室比较状态记为“未标注”，只是不触发依赖 `high` / `low` 的规则。`-` 的确切含义与 AVG 基准待甲方确认（见 [开放问题清单](./open-questions.md) Q4）。
- 有检测值但无有效参考范围时，用户可看检测值和“暂无参考范围”，不展示正常、偏高或偏低，也不执行依赖范围的规则；整份报告没有任何有效范围时，对比模块隐藏、菌门卡不显示范围。

## 8. 分析规则与报告内容

### 规则定义

- 分析规则具有草稿、启用、停用和版本。
- 规则目标从菌群字典中下拉选择一个菌门或菌属，不接受自由文本；菌属规则的命中归入所属菌门的分析单元。允许的目标层级为当前临时口径，待甲方确认（见 [开放问题清单](./open-questions.md) Q12）。
- 条件组支持“全部满足”和“任一满足”，条件只有状态类：实验室比较状态（`high` / `low` / 未标注）、相对有效参考范围状态（偏低 / 正常 / 偏高 / 无有效范围）、未检出、报告物种，以及其他分类单元的上述状态（交叉条件）。不再有绝对数值比较条件。
- 缺失只使相应判断不成立，不能据此生成健康风险、健康建议或商品推荐。
- 不向运营开放任意脚本公式。
- 规则输出为「分析」「建议」两个自由文案字段和一个风险级别（低 / 中 / 高 / 仅提示）。「仅提示」表示只出分析、不出建议、不配商品，取代原来的「仅数据完整性提示」勾选。不再区分专业结论 / 通俗解释 / 健康建议三类，也不再是“单字段分析建议、总体建议不由规则生成”。
- 规则不生成或选择商品，也不计算人工综合分、等级、百分位或平台评估维度。
- 新规则只用于之后生成或主动重新分析的报告，不自动改变已发布报告。

### “分析规则”页面边界

- 页面只维护规则定义、版本、条件、输出、优先级、冲突分组，以及一个只读的“规则测试”。
- 规则测试：选择一份报告与当前启用规则集或含草稿的候选规则集，按菌门查看命中、冲突处理结果与分析 / 建议草稿；结果不写入报告的正式分析运行、菌门分析单元、处理问题或发布版本。
- 逐份报告的正式分析运行、原始命中查看、命中排除和逐菌门确认全部在报告工作台内完成（与 ADR-0026、ADR-0031 一致）。

### 菌门分析单元

- 每份报告中每个有检测结果的菌门对应一个菌门分析单元，内含：规则命中列表、「分析」草稿、「建议」草稿、人工确认状态，以及商品推荐（0–1 个主推 SPU 加 0–3 个有序关联 SPU）。
- 每条规则命中记录来源原始菌群记录、规则版本、条件实际值和风险级别，可被人工排除但不能抹除。
- 不再有报告级的「整体分析解释」「总体建议」单例；小程序菌门详情页的「分析」「总体建议」两个 tab 读取的就是该菌门分析单元确认后的文案。
- 同一原始菌群记录命中多条规则时，以风险级别、优先级和冲突分组确定采用命中；单元内全部采用命中的「分析」输出与「建议」输出分别按风险和优先级排序，逐段原样形成草稿，不做语义改写或自动连接。「仅提示」命中只进入分析草稿。
- 审核人员可以排除命中、删除、排序、合并和改写草稿，每个菌门单独确认；无命中的菌门允许分析单元为空。
- 有效检测结果、报告物种或有效参考范围变化后，受影响菌门的草稿与确认失效，工作台显示「待重新分析」角标并阻断提交审核；审核人员主动重新运行并再次确认，系统不静默覆盖已编辑内容。
- 原始规则命中、采用结果和审核后的最终文案都要保留。

### 人工内容

当前由审核人员人工确定且彼此独立：

- 人工综合分；
- A–E 人工评定等级；
- 人工比较百分位：不填则用户端不展示「优于 x%」，不阻断发布（C4）；
- 平台评估维度：当前固定为“情绪 / 免疫”两项，由审核在综合评定手填（C3）；报告首屏四个漂浮气泡的含义待甲方确认（见 [开放问题清单](./open-questions.md) Q5）。

综合分与等级不做对应关系校验。等级只控制固定主题：A 雨林、B 森林、C 草原、D 苔藓、E 沙漠。报告中的动物称谓根据报告物种匹配，审核人员可以修正。

### 科普与素材

- 平台统一维护分类层级科普和菌群科普模板。
- “莎莎的雨林中，药草与苔藓（放线菌门）——略显繁茂”由报告宠物昵称、等级主题、菌群场景短称、菌群名称和相对范围状态词组合，用户端呈现为一条连贯文案。
- 菌群科普模板保留设计稿需要的字段：场景短称、导语比喻、主要工作列表、外观、功能，以及菌属卡片的角色 / 像什么 / 能力；原按检测状态切换的“偏低 / 正常 / 偏高提示”合并为一个不随检测状态变化的提示句（与 ADR-0020“科普不随判定状态变化”一致）。不为每个门或属复制宠物名、主题或完整句式。
- “略显稀疏 / 生机适宜 / 略显繁茂”等状态词按检测值相对有效参考范围的偏低、正常、偏高状态全局配置；没有有效范围时不追加状态词。状态词只是场景修辞，不替代分析规则生成的分析。
- 偏高、偏低、未检出等状态解释，以及当前宠物的影响和建议，由物种与结果相关的分析规则生成并进入对应菌门分析单元人工确认，不从菌群科普模板兜底。
- “某菌门包含哪些菌属”由分类树关系得到，不重复人工维护名单。
- 审核人员只能覆盖单份报告各菌门的分析与建议，不能在审核报告时修改平台菌群身份和分类关系。
- 等级背景和品牌装饰可以全局更新；直接承载专业含义的图片随报告版本固化。

## 9. 审核、发布、更正与作废

### 审核修改范围

审核人员可修改有效检测结果、报告物种、综合评定、各菌门的分析与建议以及菌门商品推荐，但不能在单份报告中手填第三套范围。有效检测结果只保留当前值、人工来源和当前修改原因，不保存逐次修改前后的值；原始检测事实继续保留，检测依据变化后要求重新确认受影响菌门的规则分析。

### 工作台动作

- 暂存只把当前编辑内容写入后端工作版本，不改变报告状态，不使用浏览器本地草稿。
- 提交审核时先原子保存当前未暂存修改和整份工作版本，再执行阻断检查；提交成功后报告进入待审核，原提交人不能继续编辑，需要修改时先撤回到待完善，撤回不改动送检记录。
- 审核人员可以直接修改报告；关系变更、状态操作和发布版本继续留痕，内容字段按各自规则保存，其中有效检测结果不保留逐次值修改链。改变专业依据时必须重新分析并重新确认发布检查。
- 审核通过后立即发布，不保留“已通过”中间状态，也不设置定时自动发布。
- 审核退回表达为“待完善 + 退回原因”，退回原因必填，不是独立状态；首期不提供字段级或模块级审核批注。
- 作废与创建更正草稿的入口在工作台顶栏（已发布时）与报告中心「更多」中。

### 固定发布检查

阻断发布：

- 尚未完成宠物建档和报告归档；
- 原始来源不可追溯；
- 报告物种未确定；
- 人工等级或综合分未填写；
- 没有任何有效检测结果；
- 任一必备预设报告模块完全没有可展示内容；
- 存在未确认的菌门分析单元；
- 有效检测结果、报告物种或有效参考范围变化后未重新分析并确认。

只警告、允许确认发布：

- 单项未决缺失；
- 某菌门的参考范围缺失或建议为空；
- 已选择商品失效或没有配置关联推荐商品。

宠物是否关联平台用户不阻断发布。以上把“未确认的菌门分析单元”列为阻断项是当前决定，分析模块的发布条件仍需甲方确认（见 [开放问题清单](./open-questions.md) Q11）。

### 更正与作废

- 已发布报告修改时创建更正草稿，报告主状态保持已发布并置「更正草稿进行中」，用户继续查看旧发布版本；报告中心显示“已发布”加“更正中·待完善”或“更正中·待审核”副标签。
- 同一报告最多存在一个活动更正草稿；已有更正草稿时继续进入该草稿，不允许并行创建多个候选版本。
- 新版本审核发布后替换当前版本；用户只看到最新版本和最近更新时间，不看版本号、旧内容或变更摘要。
- 旧版本仅管理端可追溯。
- 报告作废后立即从用户端消失，但原始文件、版本和操作记录保留。
- 报告归错宠物或宠物关联错用户时，由运营直接修正并立即生效；管理端保留更正前后关系、操作人员、时间和原因。

## 10. 用户、宠物与报告关联

- 宠物由运营在登记送检时根据电话或微信核对结果创建并维护，作为履约对象关联到该用户；不是脱离送检的空档案，也不等到首次报告归档才建档。
- 小程序宠物资料完全只读，不提供新增、编辑、纠错申请、重复判断或合并。
- 运营登记送检时，根据手机号、宠物名称、物种和品种等基础信息人工搜索并选择已有宠物或创建宠物，不做自动判重、评分或合并。
- 运营为宠物选择已注册平台用户；样本编号可从试管标签或微信补填，Excel 不含身份字段，不自动决定关联。
- 宠物可以暂时不关联用户，报告仍可继续审核发布；建立关联后，用户自动获得该宠物全部已发布报告的查看权。
- 不提供领取码、扫码认领、用户确认、用户拒绝或用户自行修改关联关系的流程。
- 报告归错宠物或宠物关联错用户时，运营直接修正并填写原因；系统保留变更前后关系、操作人和时间。

## 11. 小程序业务范围

v1 实施方式已锁定（产品负责人确认，原开放问题 Q10 已收入第 0 节）：在现有商城小程序同一 AppID 内二次开发健康报告模块，不新建报告小程序，也不做跨小程序跳转。复用商城既有登录态、商品详情、购物车、订单、支付和退款能力；健康报告模块新增页面、路由、主导航与商品详情衔接。小程序启动/登录默认进入健康报告首页，主导航按原型为「首页」「我的」。用户端仍不提供宠物新建、编辑、认领或分享。

### 健康报告首页

「健康报告首页」即小程序启动/登录后的全局默认首页，为当前宠物页；不再默认商城原首页、经营看板或第二份宠物列表。

- 小程序启动/登录默认进入健康报告首页；无路由时固定落在健康报告首页。即使只有一只宠物和一份报告，也不自动跳过该页，也绝不自动打开报告。
- 问候语使用宠物档案名，而不是登录用户名。
- 一只宠物：主区块要么是不可点击的「报告处理中」（自送检登记起至发布），要么进入该宠物最新一份已发布报告；其下是该宠物历史已发布报告的同一份列表，不在其他报告页面重复放第三份列表。
- 多只宠物：页面头部提供紧凑宠物切换器；切换后整页换成该宠物的报告首页内容。没有完整宠物列表页，也没有「最多三只 + 全部宠物」跳转。
- 没有宠物：显示「暂无宠物，请联系门店」，联系路径复用商城已有客服或门店入口，不发明用户侧 onboarding。
- 不提供跨宠物「全部报告」、领取报告、待确认报告或后台处理进度入口。

「我的」页按健康报告原型调整：展示微信头像、手机号与「资料有误请联系运营」；可复用商城已有身份数据与客服能力，但不放入宠物列表、报告、通知或设置。

### 报告查看

- 从健康报告首页主区块或该宠物历史已发布列表打开报告，作为独立页。
- 阅读结构跟视觉设计：先是等级主题首屏；底部「详细」滚入对比（仅当存在有效参考范围）再滚入菌门分段。废除「概览 / 对比 / 菌门」三 tab 报告信息架构。不要把报告首屏称为「健康报告首页」。
- 管理端工作台右侧预览必须同一套：一页滚动的小程序报告，不是三个 tab。
- 主题首屏承载综合概览：宠物称谓、等级、综合分、人工百分位、核心指标和等级主题。
- 报告首屏三个摘要指标固定为 Alpha 多样性、均匀度和丰富度。v1 闭环：工作台可补录这三项；不填则原位置显示“暂无有效结果”，不自动换成其他指标，也不单独阻断发布。三个位置固定。以后是否改成机构给或公式算见 [开放问题清单](./open-questions.md) C2，不挡出报告。
- 平台评估维度当前固定为“情绪 / 免疫”两项，由审核手填（C3）；主题首屏插画上四个漂浮气泡的含义待甲方确认（Q5）。
- 综合概览和有效检测结果是发布必备核心内容：综合概览必须具备已关联宠物、明确报告物种、人工等级和综合分，有效检测结果至少包含一项有效数值或明确未检出。三个摘要指标允许个别缺失。
- 菌群对比在至少一项结果具有有效正常范围时出现在「详细」滚动区内，没有任何有效范围时隐藏整个模块，菌门卡也不显示范围，也不拼「略显稀疏 / 生机适宜 / 略显繁茂」；无范围仍可发布。具体菌门或菌属只在存在有效结果或明确未检出且被报告内容选中时出现。
- 菌门详情页的“分析”“总体建议”两个 tab 读取该菌门分析单元确认后的分析与建议；“总体建议”tab 下展示该菌门的主推商品卡。商品在小程序中的最终位置与卡片形式仍待甲方确认（见 [开放问题清单](./open-questions.md) Q8），这是当前口径。
- 菌门建议和商品推荐均不阻断发布；没有建议或可用商品时不制造空白区域。分析模块的发布条件当前按“存在未确认的菌门分析单元即阻断”执行，最终标准待甲方确认。
- 每个必备模块以少量业务必需内容判断是否非空，不根据填写字段数量计算百分比。
- 专业内容只展示本次实际检测到、明确未检出或经审核选入报告的分类和检测项，不展开整棵分类树，也不只保留异常项目。
- 菌门详情可以继续查看检测值、有效范围（存在时）、所含菌属、分析和建议。
- 同一菌门同时提供专业数值、有效范围、所含菌属、分析和建议，不拆成两套完整报告。
- 分析与建议文案使用受限的结构化内容，支持段落、列表、强调和专业图片；商品卡由菌门分析单元的商品推荐项产生，不通过正文中的推荐位编码插入；不允许任意 HTML、脚本或自由页面布局。
- 未检出明确显示“未检出”；缺失项不显示数值，固定位置必要时显示“暂无有效结果”。
- 任一预设模块完全为空会阻断发布，因此用户不会看到完整空模块。
- 用户只能查看当前发布版本，不看后台报告版本历史。
- 不提供跨多次检测的趋势图；设计图中的理想菌群对比属于单份报告内部对比。
- 平台不发送发布通知，也不展示统一健康免责声明。

## 12. 健康建议与商城联动

### 推荐模型

商品推荐挂在菌门分析单元上，每个单元最多包含：

- 一个运营人工选择的主推 SPU；
- 最多三个运营人工选择并排序的可选关联推荐 SPU。

商品推荐项不保存推荐理由或建议文案，跟随该菌门确认后的建议出现；风险级别为“仅提示”的菌门不配置商品。系统不维护健康需求标签、标签商品映射、推荐评分或自动排序，也不根据检测结果、报告物种、库存或商城分类自动选择商品；原型中的健康需求标签与标签商品映射数据一并删除。商品部分允许完全不配置，不阻断报告发布。

- 小程序中，主推商品卡展示在对应菌门详情页“总体建议”tab 下（当前口径，最终位置与卡片形式待甲方确认，见 [开放问题清单](./open-questions.md) Q8）；正文不平铺关联推荐商品。
- 推荐详情按运营手工顺序展示主推商品之外最多三个关联推荐商品；系统只根据商城状态标记是否可购，不改写人工顺序。
- 可购的主推商品从商品卡直接进入商城 SPU 详情；下架、缺货或已不存在的主推商品仍作为原推荐上下文展示，点击后进入推荐详情查看替代商品。

运营通过报告工作台“商品推荐”模块按菌门维护商品配置，模块列出各菌门的建议摘要与商品槽；商品配置放在独立模块还是并入菌门卡片，甲方未确认，当前口径为独立模块。商品配置与专业报告版本分开，保存后立即更新该报告当前的小程序展示，不创建报告更正版本；系统不跨报告复用或自动传播商品选择，也不因其他报告的商品调整而改变当前报告。

### 商品状态处理

| 商城状态 | 报告行为 |
| --- | --- |
| 主推 SPU 正常上架且可购 | 展示主推商品，点击直接进入商城 SPU 详情 |
| 主推 SPU 上架但库存为 0 | 保留并展示原主推商品，点击进入推荐详情查看人工配置的关联推荐商品 |
| 主推 SPU 不存在、回收或下架 | 保留原主推商品关系和展示上下文，工作台显示「商品失效」角标，点击进入推荐详情查看人工配置的关联推荐商品 |
| 没有任何可用关联推荐商品 | 仍完整展示该菌门建议和原主推商品上下文，不制造可购买入口 |

用户选择当前可购商品后，在同一商城小程序内进入现有 SPU 详情并自行选择 SKU。不可购的原主推商品不进入商城详情，而进入健康报告模块的推荐详情查看替代商品。健康报告模块不自行处理购物车、订单或支付，而是交给商城既有交易链路；首期不记录商品点击。

商品卡读取商城当前或历史保留的图片、名称和状态，并读取当前价格、库存和可购状态；系统不自动替换、补充或重排运营选择的商品。报告不复制商品资料、规格和促销规则。首期不记录报告商品点击，也不建设加购、订单或支付归因。

### 现有商城的改造边界

健康报告将在现有商城小程序内二次开发，因此商城小程序前端需要新增或调整：健康报告入口、页面注册与分包、模块路由、登录态复用、商品详情衔接、返回路径以及真机适配。以下既有交易能力原则上复用，不重新建设：

- 商城已经提供 SPU 查询、批量查询、有效性校验和商品详情能力；
- SKU、价格、库存、购物车、订单、支付、退款和上下架状态继续由商城负责；
- 报告模块只保存各菌门分析单元中运营选择的主推 SPU、可选关联推荐 SPU 和人工顺序；
- 报告模块使用现有商城能力批量取得实时商品事实，不建设商品推荐解析服务；
- 商户号、支付权限、AppID 绑定、支付密钥和回调继续由商城既有后端管理，健康报告前端不得持有支付密钥。

管理端商品选择优先复用现有商品分页接口和商品选择弹窗的结构，在工作台商品推荐模块内提供商品名称、商品编号、分类和状态筛选，并允许从在售、下架、缺货和回收站商品中选择。已经逻辑删除的历史商品继续按既有关联 SPU 标识读取和展示，但不重新进入可搜索商品池。

如果现有接口不能满足报告商品卡、身份关联或路由衔接，可在商城边界增加最小兼容接口；若未来要求按报告来源追踪加购、订单和支付，则另行设计归因链路，当前明确不做。

商品推荐跟随对应菌门的建议出现，使用户能够理解商品与哪一菌门的分析相关；每个菌门只放一个主推商品卡，推荐详情最多展示三个由运营人工选择和排序的关联推荐商品。

## 13. 管理端功能清单

管理端登录后直接进入报告中心，不设置业务首页。

### 送检管理

- 送检管理是与报告中心并列的业务入口，处理登记送检后、报告生成前的运营履约，不命名为笼统的“待处理任务”。
- 默认提供待导入结果、导入异常和全部送检三个视图；待导入结果是默认工作队列，导入异常用于重新导入，全部送检用于追溯。
- 页面提供登记送检，以及从该送检记录发起的导入结果和重新导入；不再设独立的 Excel 导入页，也不在列表上提供无预登记批量导入。登记送检时创建或选择已关联平台用户的宠物。
- 导入结果把一份 Excel 挂到当前送检记录；多文件只表现为 N 条待导入送检记录配对 N 个文件。导入结果包括成功、失败与异常、失败原因、失败文件重新上传，以及原始 Excel 查看与下载。
- Excel 成功导入并生成唯一报告后，送检记录显示“已生成报告”并退出默认工作队列；报告进入待完善（宠物已存在）。报告的待归属、待完善、待审核、已发布和已作废不再作为送检记录状态。待归属仍留在模型中，但不是 v1 入口。
- 已生成报告的送检记录提供查看报告入口；报告中心只提供“查看送检记录”反向入口，不承接重新导入。

### 报告中心

- 全部、待归属、待完善、待审核、已发布和已作废视图；不另设已发布报告列表页。待归属仅作为模型遗留状态保留，不是 v1 入口。
- 报告中心从 Excel 成功解析并生成报告后开始，不包含登记送检、等待机构出结果或导入异常处理。
- 默认进入“待处理”聚合视图，只包含待完善和待审核报告，不把待归属算进待处理；“待处理”不成为新的报告状态；全部、已发布和已作废用于档案查询与追溯。
- 各状态视图显示当前查询条件下的结果数量，不显示与当前查询无关的全局数量。
- 默认展示综合搜索和来源机构，并提供展开按钮显示物种与检测日期等高级筛选；综合搜索覆盖平台报告编号、外部报告编号、样本编号、手机号和宠物名称，报告状态只通过顶部视图切换。
- 不提供待办标记筛选，列表不显示待办标记。
- 列表只显示报告主状态和更正副标签，不展示预设报告模块完整度或具体处理问题；缺失模块、数据异常、待重新分析和发布条件等进入单份报告工作台后查看。
- 单份报告按来源与归属、检测结果、综合评定、分析与建议、商品推荐、发布检查、版本与记录七个模块组织。
- 只允许逐份执行完善、审核、发布、作废和纠错（改归宠物 / 换用户）。
- 列表采用保持扫描效率的紧凑记录卡，每份报告内部按报告标识、用户与宠物、检测来源、流程状态、更新时间和操作六组信息组织，不继续拆成十个刚性表格列，也不使用占据大量纵向空间的大卡片。
- 待归属报告若出现，显示“未归属 · 导入文件名 · 送检编号（若有）”；Excel 中没有客户姓名、手机号等任何身份信息，列表不展示不存在的导入客户信息。v1 主路径不产生待归属。
- 已发布报告存在更正草稿时仍归入已发布视图，主状态显示“已发布”，并附加“更正中·待完善”或“更正中·待审核”副标签，不拆成两条报告记录。
- 每条记录根据状态只显示一个主要动作，例如继续完善、审核或查看；“更多”收纳版本、作废和创建更正草稿，并提供“查看送检记录”。
- 待处理视图按进入当前状态的时间从早到晚排列，优先暴露滞留报告；全部、已发布和已作废等档案视图按最近更新时间倒序排列。

### 报告工作台与实时预览

- 编辑、完善和审核共用同一个报告工作台，左侧按报告模块处理数据与内容，右侧以模拟小程序展示当前工作版本。
- 左侧按运营处理对象组织为来源与归属、检测结果、综合评定、分析与建议、商品推荐、发布检查、版本与记录七个一级模块，不照搬小程序阅读页面，也不按数据库表暴露技术结构。
- 待完善报告恢复上次编辑位置，待审核报告默认进入审核总览；若出现待归属报告则默认进入来源与归属。状态发生变化后不继续停留在已经失效的入口。
- 已发布报告的工作台顶栏提供作废与创建更正草稿入口。
- 模块导航分别显示必须处理的阻断数和允许确认后继续的警告数，问题同时出现在对应字段附近；待重新分析、缺失未处理、商品失效、未关联用户以角标形式提示，不把所有问题堆到页面顶部或等到发布时才首次展示。
- 页面提供明确的“暂存”按钮，将当前编辑内容保存到后端工作版本但不改变报告状态；系统不以自动保存或浏览器本地草稿替代后端暂存，尚未暂存的修改离开页面前必须提示。
- 工作台内切换模块时保留当前页面会话的全部未暂存修改，不要求逐模块暂存；暂存时原子保存整份工作版本，多次暂存更新同一工作版本并记录暂存人和时间，不为每次暂存生成正式报告版本。
- 多人同时编辑时不锁定报告，也不校验工作版本冲突，后一次暂存直接覆盖前一次暂存；平台接受由此产生的先前修改丢失风险。
- 左右区域支持拖动调整宽度，右侧预览可以临时收起；较窄屏幕优先保留编辑区，并将预览收进右侧抽屉，不强制横向滚动。
- 右侧预览与小程序一致，为单页滚动的报告阅读页（主题首屏 →「详细」滚入对比与菌门分段），不再使用「概览 / 对比 / 菌门」三个 tab；默认展示包含未暂存修改的工作版本，并明确标记为工作版本预览，实时预览不等于暂存或发布。
- 文字、图片、人工分值等直接呈现内容修改后实时更新；检测值、报告物种、有效参考范围等专业依据变化时，先说明影响并由操作人员确认重新分析，不静默覆盖人工调整过的分析与建议。
- 鼠标悬停左侧字段时，如果目标位于当前预览滚动区内则临时定位；点击或聚焦字段后才滚到对应分段或钻入菌门详情，避免移动鼠标时连续跳动。
- 点击或聚焦字段后，目标区域滚动到可见位置，并使用清晰描边、轻遮罩和字段名称提示；短暂动效结束后保留弱高亮，不能只依赖闪烁或颜色表达对应关系。
- 点击右侧可编辑展示区域时，工作台反向切换到负责该内容的左侧模块并聚焦字段。
- 一个字段影响多个位置时显示影响位置数量和位置清单，由用户逐个查看，不自动假定唯一主要位置，也不同时打开多个手机预览。
- 没有直接用户端展示位置的字段不制造虚假高亮，右侧明确提示“此项不直接展示”，并说明它影响分析、参考范围、推荐或发布检查。
- 已发布报告进入更正时，通过同一个预览设备切换“工作版本”和“当前线上版本”，并提供变化位置导航，不长期并排展示两个手机。
- 检测结果模块采用可搜索的主从结构，支持异常、缺失和已修改筛选；选中一个普通指标或菌群后在侧边详情区编辑，不将全部结果展开为超长表单或拆成独立页面。
- 检测结果模块对每条记录展示 Excel 原始值与当前有效值的对照、范围来源（报告导入 / 平台配置 / 无有效范围）和实验室比较状态（`high` / `low` / 未标注）；允许修改有效值并填写原因、补录缺失项。`vs AVG notice` 为 `-` 的记录正常展示，不被剔除。
- 当前有效结果存在人工修改时标记“已修订”，默认展示当前值，展开后可以查看 Excel 原始值和当前修改原因；不展示逐次修改版本链。
- 来源与归属模块展示原始 Excel 的文件名称、上传时间和模板识别结果，并提供查看与下载。
- 未知检测项保留原始内容并进入待确认处理，运营在工作台侧边表单中关联已有检测项或登记新的平台检测项，完成后返回当前报告；系统不按名称自动创建。
- 缺失结果在检测结果模块内人工补录并标记人工来源，原始缺失状态继续保留；无法解析的数值保留原始文本，有效结果保持为空，修正前不参与范围判断和分析。不再有独立的补录或完善指标页面。
- 报告物种与宠物档案物种不一致时显著提示，审核人员可以确认报告物种，但不自动覆盖任一方。
- 分析与建议模块按菌门卡片展示：每张卡片包含该菌门的规则命中列表（含来源原始菌群记录、规则版本、条件实际值、风险级别，可排除）、「分析」与「建议」草稿以及确认状态；每个菌门单独确认。
- 商品推荐模块按菌门列出建议摘要与商品槽（0–1 主推、0–3 有序关联）；是否并入菌门卡片待甲方确认。
- 修改检测值、报告物种或有效参考范围后，先列出受影响的菌门、分析和推荐，默认只重新生成受影响菌门的内容，同时提供重新分析整份报告的入口。
- 审核人员默认先进入审核总览，查看本次提交的修改范围、阻断项、警告和关键专业数据，再按需进入具体模块。
- 发布检查作为独立模块持续展示当前检查结果，其中“存在未确认的菌门分析单元”和“依据变化后未重新分析”为阻断项；提交审核或发布时再打开最终确认面板，最终面板不承担第一次发现问题的职责。

### 用户与宠物

- 查询平台用户并辅助手机号核对。
- 在登记送检时选择已有宠物或创建宠物（履约对象，不是空档案）；不提供脱离送检、为建档而建档的空档案入口。
- 宠物档案首页只展示宠物列表；宠物详情展示最小识别资料、当前关联用户和已发布历史报告。
- 待归属不是 v1 入口；关联纠错记录放在对应宠物或报告详情，不在宠物档案首页设置全局工作台。
- 运营直接修正报告与宠物、宠物与用户的关联，并保留原因和操作记录。

### 专业配置

- 普通检测指标。
- 菌群分类树、分类层级科普和菌群科普模板（字段见 §8 科普与素材，提示句不随检测状态切换）。
- 平台参考范围。
- 分析规则：规则定义、版本、条件、输出、优先级、冲突分组，以及只读的规则测试；不提供逐份报告的正式分析运行。
- 无效推荐商品在工作台以角标提示；不设置健康需求标签、标签商品映射或推荐映射菜单。

### 明确不做

- 管理端业务首页和经营分析看板。
- 独立的已发布报告列表页、旧的宠物报告管理页、独立 Excel 导入页和推荐映射页。
- 无预登记批量导入，以及把等待机构出结果伪装成报告中心任务。
- 机构资料与 Excel 模板配置页面。
- 批量归属、批量审核和批量发布。
- 会员、积分、消费、回访和客户营销。
- 最终报告 PDF 或 Word 导出。

## 14. Mock 演示场景

演示数据至少覆盖：

1. 从已登记送检记录导入：正常文件、重复文件、局部异常和关键失败；多文件只演示 N 条待导入送检记录配对 N 个文件。
2. 成功导入后报告进入待完善（宠物已在送检登记时存在）；不把待归属作为必做演示入口。
3. 运营为宠物关联平台用户；未关联用户时报告仍可继续处理和发布。
4. 运营在检测结果模块补录缺失值、处理新检测项、确定范围，并重新生成受影响菌门的分析。
5. 审核人员填写综合评定、逐菌门确认分析与建议、为需要承接的菌门配置主推商品并发布。
6. 用户启动/登录默认进入健康报告首页查看当前宠物：主区块为「报告处理中」或进入最新已发布报告，其下为该宠物历史已发布列表；从健康报告首页打开报告阅读页（主题首屏 →「详细」→ 对比与菌门分段），并在菌门详情页查看该菌门的分析、建议与主推商品卡。
7. 已发布报告创建更正草稿，旧版本继续可见，新版本发布后替换。
8. 主推商品下架后保留原商品状态并出现「商品失效」角标，运营可以在工作台商品推荐模块人工更换主推或补充关联推荐商品。
9. 运营将报告改归正确宠物或更换宠物关联用户，并在对象详情查看纠错记录。
10. 报告作废后从小程序消失但后台仍可追溯。
11. 审核退回后报告回到待完善并显示退回原因；`vs AVG notice` 为 `-` 的菌属正常展示为“未标注”且不触发规则。

## 15. MVP 验收标准

- 已知 Excel 模板可从送检记录导入，每个文件独立处理，原始文件可追溯；不支持无预登记批量导入。
- 重复报告、关键异常、局部异常和待确认检测项符合既定规则。
- 原始事实、有效结果、规则命中、审核内容和发布版本之间边界清晰。
- 分析、建议与商品按菌门分析单元组织，每条规则命中可追溯到来源原始菌群记录与规则版本，每个菌门单独确认后才能提交审核。
- 报告只有五个主状态，加“更正草稿进行中”和“退回原因”两个字段；待办标记仅在工作台以角标出现。
- 运营能够完成送检登记时建档宠物、从送检记录导入、补录、审核、发布、更正、作废和纠错（改归宠物 / 换用户）。
- 用户无需领取或确认；启动/登录默认进入健康报告首页（当前宠物页），只读查看处理中占位与全部已发布报告。
- 未发布报告、旧版本、失败报告和作废报告不向用户展示。
- 主推 SPU 和人工关联推荐 SPU 能读取商城实时状态，系统不会自动替运营更换或重排商品。
- 现有商城小程序前端已完成健康报告入口、路由、页面/分包及同小程序商品详情衔接；商城交易后端继续复用。
- 所有代表流程均有稳定 Mock 数据，能够重复演示且不依赖真实机构、真实微信用户或真实订单。

## 17. 现有原型需要校正的业务点

以下为 2026-09-02 决定后原型仍需校正的差距，按决定编号列出：

- D1 分析与建议按菌门产出：原型仍以报告级“整体分析解释”“总体建议”单例组织，需要改为每个有结果的菌门一个分析单元（命中列表、分析草稿、建议草稿、确认状态、商品推荐）。
- D2 规则输出：分析规则页仍是“专业结论 / 通俗解释 / 健康建议”三类，需改为“分析”“建议”两个字段加风险级别（低 / 中 / 高 / 仅提示），并移除“仅数据完整性提示”勾选。
- D3 规则目标：仍为自由文本，需改为从菌群字典下拉选择菌门或菌属，属级命中归入所属菌门（临时口径）。
- D4 规则条件：需删除绝对数值比较条件，只保留实验室比较状态、相对范围状态、未检出、报告物种和交叉条件。
- D5 分析规则页：只保留规则维护与只读的按菌门“规则测试”，移除逐份报告运行、命中排除等入口。
- D6 报告工作台：模块改为来源与归属 / 检测结果 / 综合评定 / 分析与建议 / 商品推荐 / 发布检查 / 版本与记录；分析与建议按菌门卡片并逐菌门确认；商品推荐按菌门列出建议摘要与商品槽；发布检查加入“存在未确认的菌门分析单元”“依据变化后未重新分析”两个阻断项。
- D7 工作台动作：去掉浏览器本地草稿，暂存只写后端；提交审核前执行阻断检查；撤回不改动送检记录；审核退回改为“待完善 + 退回原因”；去掉“已通过”中间状态；作废与创建更正草稿入口放到顶栏（已发布时）和报告中心“更多”。
- D8 检测结果模块：展示 Excel 原始值与有效值对照、修改原因、补录、范围来源与实验室比较状态；`vs AVG notice` 为 `-` 的记录正常展示为“未标注”，不再默认剔除。
- D9 工作台右侧预览改为与小程序一致的单页滚动报告（主题首屏 →「详细」滚入对比与菌门分段），不再使用「概览 / 对比 / 菌门」三 tab。
- D10 报告状态收敛为五值加“更正草稿进行中”“退回原因”；删除“审核退回”“已通过”“已更正”及所有领取相关状态；待办标记只保留四类且仅在工作台角标显示。
- D11 报告中心：增加更正副标签；待归属行改为“未归属 · 导入文件名 · 送检编号（若有）”，去掉 Excel 中不存在的客户姓名与手机号；“更多”含版本 / 作废 / 创建更正草稿；“重新导入”移入送检管理，报告中心只留“查看送检记录”。
- D12 删除页面：已发布报告列表页、旧的宠物报告管理页、独立 Excel 导入页、业务首页 / 看板、推荐映射页；删除健康需求标签与标签商品映射 Mock 数据；补录 / 完善指标能力并入工作台检测结果模块。
- D13 小程序：在现有商城小程序同一 AppID 内新增健康报告页面、路由、分包与主导航（「首页」「我的」）；启动/登录默认进入健康报告首页（当前宠物页，多宠头部切换，无宠「暂无宠物，请联系门店」），报告从该页打开为独立滚动页（主题首屏 →「详细」→ 对比（若有）→ 菌门分段），不再使用「概览 / 对比 / 菌门」三 tab；菌门详情页“分析”“总体建议”tab 读取菌门分析单元文案，建议 tab 下展示该菌门主推商品卡（临时口径），可购商品在同一小程序内进入现有商城商品详情；健康报告首页问候语使用宠物档案名；无任何有效范围时对比模块隐藏、菌门卡不显示范围；移除领取报告等已废止入口。
- D14 菌群科普模板：把“偏低 / 正常 / 偏高提示”三个字段合并为一个不随检测状态变化的提示句，其余设计稿字段保留。
- 通用：报告状态、待办角标、归属、菌门分析单元、版本和商品状态必须由同一套 Mock 数据贯通；此前已列出的用户端只读约束（不展示旧版本、宠物资料只读、无领取与后台进度入口）继续有效。
