# 宠物健康报告开放问题

以下事项尚未形成产品决策，不得直接作为实现要求。

## 待甲方确认

### 检测项目与报告类型

- 当前产品是否长期只提供宠物微生物组检测，还是需要建立可扩展的检测项目或报告类型。
- 如果未来增加其他检测项目，它们是否分别拥有 Excel 模板、检测指标、分析规则和预设报告模块。

在甲方确认前，不能把“只支持一种报告”或“首期即建设多报告类型配置”作为实现要求。

### 必备报告模块

- 每一种报告类型必须包含哪些预设报告模块。
- 每个模块至少具备哪些数据或人工内容才算“非空”并允许发布。

已确认单个检测项缺失可以发布，但任一必备模块完全没有可展示内容时阻断发布；具体最低完整性需甲方确认。

### 小程序默认首页

- 登录后默认进入“我的”，还是自动打开检测日期最新的一份已发布报告。
- 无已发布报告以及存在多只宠物、多份报告时采用何种默认落点。

已确认小程序“我的”提供宠物、报告和领取报告入口；默认首页尚不能作为实现要求。

### 商品推荐的用户端呈现

- 商品推荐出现在分析文字中、固定区域还是独立页面。
- 一个推荐位展示多少候选商品，以及采用何种卡片或列表形式。
- 同一健康需求标签下候选商品的最终排序和“查看更多”方式。

已确认的底层边界不受此问题影响：报告支持推荐位，推荐解析结果包含主推商品、健康需求标签和可用候选商品。

### 首页摘要项

- 所有报告采用平台固定摘要项，还是允许审核人员按报告调整。
- 首页摘要项的默认数量、可替换范围以及缺失时的展示方式。

### 微生物组对比基准

- 真实 Excel 提供的是完整上下限、仅上限，还是另有理想目标值。
- 设计图中的 0 是图表坐标起点，还是部分指标参考范围的真实下限。
- 同时存在正常范围与理想目标时，暂按“范围判断状态、目标仅作参考位置”设计，仍需甲方确认。

当前设计图中已经出现 2%–8%、12%–20%、15%–30%、40%–65% 等非零下限，不能先假定所有正常范围都从 0 开始。
