## Excel 实际有什么

三份文件都是单 sheet（`leaky gut microbiota`），只有 9 列：

`superkingdom` · `phylum` · `class` · `order` · `family` · `genus` · `species` · `Your sample (%)` · `vs AVG notice`

没有：宠物 / 用户 / 样本 / 报告编号、检测日期、参考范围、现成的菌门合计、Alpha 多样性 / 均匀度 / 丰富度、情绪 / 免疫、综合分 / 等级 / 百分位、维生素或其他评估维度、分析文案、建议文案、商品。

补充事实：

- `class` / `order` / `family` 三列全是占位值 `Class_` / `Order_` / `Family_`，不能用来分类。
- `species` 多数为 `unresolved`，少数有种名。
- 只有属级行；同一 `genus` 会占 1–13 行（harley 最多 8 行，oscar 9 行，riley 13 行）。
- 约 20 个属。`vs AVG notice` 只有 `high` / `low` / `-`。
- 占比合计分别为约 100.01% / 120.80% / 134.97%，不是 100%。
- 文件名是 `harley_final_microbiome_report.xlsx` 这类宠物名，表内没有任何身份字段。

设计稿见 `docs/product-design/img/`。科普文案、动物隐喻、主题插画是平台素材，不向 Excel 要。分析 / 建议文案来自规则 + 人工审核，也不向 Excel 要。

## 0. 已内部决定（知情即可，不必再议）

1. **送检与导入**：先登记送检，再把 Excel 挂到那一条送检记录上。身份（用户、宠物、送检日、承接门店、检测机构、平台送检 ID、送检类型）由平台在导入前写好。原「检测机构 / 来源」已拆成两个字段：承接门店（承接该案的商户门店，两种类型均必填）与检测机构（出具 Excel 的实验室；本店送检通常填写，客户自带报告可选）。送检类型为本店送检或客户自带报告：本店送检主按钮为「确认登记」，不自动打开文件选择；客户自带报告主按钮为「登记并导入」，登记成功后立即打开文件选择，取消选择不是失败（记录已存在，可稍后在该行导入）。两条路径都是先选定已关联用户的宠物再登记，再在该行导入。关键词搜索覆盖送检 ID、样本编号、手机号、宠物名；登记成功后高亮并滚到新行。样本编号仍可选，空值不参与判重；重复判定只在同一检测机构内。平台送检 ID 与报告号全局唯一。不做「无预登记批量导入」，界面不把待归属作为可操作状态。宠物在登记送检时创建（履约对象，不是空档案）。
2. **没有参考范围也可以出报告**：对比模块整块隐藏；菌门 / 菌属卡不显示正常范围，也不拼「略显稀疏 / 生机适宜 / 略显繁茂」。设计稿里的 2%–8%、12%–20%、15%–30%、40%–65% **不能进生产**。不允许在单份报告里手填第三套范围。平台范围方案由「指标/参考范围」维护（见第 0 节第 7 条），不是出报告的前提。
3. **商品推荐**：运营在单份报告的各菌门里人工选商城 SPU；每菌门最多 1 个主推 + 3 个关联；不做推荐算法。小程序最终摆放位置仍见第 3 节。
4. **建设范围**：内部按「只支持微生物组报告」建设（ADR-0023）。是否对外承诺永远只有这一种，见第 3 节。
5. **现有商城小程序内二次开发（原 Q10）**：已锁定，不再作为待拍板项。宠物健康报告作为现有商城小程序同一 AppID 下的新增模块，不新建报告小程序，也不做跨小程序跳转；复用商城已有登录态、商品详情、购物车、订单、支付和退款能力，新增健康报告页面、路由与商品详情衔接。健康报告模块不另建交易后端，也不保存支付密钥。小程序启动/登录默认进入「健康报告首页」= 当前宠物页，主导航按原型为「首页」「我的」。即使一宠一份报告也不跳过健康报告首页，也绝不自动打开报告。健康报告首页不是经营看板也不是第二份宠物列表：一只宠物时问候用档案名，主区块为不可点击「报告处理中」（自送检登记至发布）或进入最新已发布报告，其下为该宠历史已发布的同一份列表；多宠时头部紧凑切换并替换页面内容，没有完整宠物列表页；无宠时显示「暂无宠物，请联系门店」。报告从健康报告首页打开为独立滚动页（主题首屏 →「详细」滚入对比与菌门分段），不再用「概览 / 对比 / 菌门」三 tab。用户端仍不提供宠物新建 / 编辑 / 认领 / 分享。
6. **分析规则 v1**：适用范围是封闭物种名单，一条规则只属于一个当前能出报告的物种；禁止开放「全部（含未来新物种）」。主证据是实验室标注 high / low / 未标注或未检出，可另加有效值百分比门槛；两者同时填写时必须都满足才命中（AND）。同一个数字对所有已知检测方案 / 实验室生效，方法不同导致一边命中一边不中由运营承担——这是明确接受的专业风险。同一菌上多条命中全部采用，不再用风险级别自动裁冲突。没有「仅提示」档；建议栏空着 = 不给建议；商品由工作台决定。规则里的分析/建议是可复用草稿，每份报告仍须在工作台按菌门确认后发布。需要给另一物种写相同判断时复制成新谱系。
7. **「指标/参考范围」P0–P4**：管理端方案编辑已内部拍板（ADR-0037）。范围项可搜索绑定专业基础资料，类型与层级只读回填；行上移 / 下移与「在此下方插入」，拖拽非 v1；方案内顺序只方便编排，用户端对比跟随本份有效结果与分类树。不要求「参考依据说明」；`templateId` 从已知模板选择；同一（模板, 物种）至多一个启用方案。保留整方案复制，另可复制范围项、可选按菌门字典预填空行。平台方案由专业资料权限维护，报告工作台不改方案。将来若 Excel 带入范围，工作台确认可用或驳回（驳回后回落平台方案或空），仍禁止手填第三套范围；当前 Excel 无范围，该交互为前瞻。没有有效范围仍可出报告。

## 2. 已闭环：工作台能补上，不挡出报告

这些字段 Excel 里都没有，但产品已经规定谁填、填在哪、缺了怎么展示。v1 按此发报告。跟甲方确认的是「以后要不要改成机构给或公式算」，不是今晚的阻塞项。

### C1. 参考范围

**闭环：** 没有有效范围时对比模块隐藏，菌门 / 菌属卡不显示范围，也不拼「略显繁茂」。单份报告不允许手填第三套范围（避免运营把设计稿上的 2%–8% 填进生产）。平台范围方案由管理端「指标/参考范围」维护（P0–P4 已内部拍板，见第 0 节），不是出报告的前提。将来若机构 Excel 带入范围，工作台确认可用或驳回，驳回后回落平台方案或空。

可选确认（不挡 v1）：机构会不会另给整套正常下限 / 上限？若会，请说明文件形式、是否分猫犬、多久更新。管理端方案怎么编、谁维护，不必再议。

### C2. Alpha 多样性、均匀度、丰富度

**闭环：** 工作台可补录这三项。不填则原位置显示「暂无有效结果」，不换成别的指标，也不单独阻断发布。三个位置固定。

可选确认：要不要改成机构另给（另附一列或另一张表），或平台按属级丰度计算（需指定算法）。不改就维持人工补录。

### C3. 情绪、免疫

**闭环：** 审核在综合评定手填。这是平台评估维度，不是实验室检测值。

可选确认：要不要改成计算公式或机构另给。不改就维持人工填写。也可以首期去掉这两项。

### C4. 综合评分 A–E、综合分、「优于 x% 的猫咪」

**闭环：** 三项都由审核手填，三者不强行对应。等级只决定主题（A 雨林 / B 森林 / C 草原 / D 苔藓 / E 沙漠）。发布要求有等级和综合分；百分位不填则不展示「优于 x%」。不声称来自实验室或真实历史样本。

可选确认：要不要改成评分公式或真实群体统计。不改就维持人工填写。也可以只保留等级主题，去掉综合分和百分位。
