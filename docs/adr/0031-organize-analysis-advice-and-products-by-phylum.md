# 分析、建议与商品按菌门组织

每份报告中每个有检测结果的菌门对应一个菌门分析单元，内含规则命中列表（每条命中记录来源原始菌群记录、规则版本、条件实际值和风险级别，可被人工排除）、「分析」草稿、「建议」草稿、人工确认状态，以及最多一个主推 SPU 加最多三个有序关联 SPU 的商品推荐；报告不再保留报告级的「整体分析解释」「总体建议」单例。选择菌门作为组织粒度有三个依据：设计稿把「分析」「总体建议」两个 tab 放在每个菌门页内，报告级单例没有对应的展示位置；真实 Excel 的 `vs AVG notice` 是属级判断，属级命中可以按所属菌门聚合，不需要预先归并跨门内容；商品与建议同处一个菌门单元，避免同时维护报告级单例与逐条建议商品两套模型。分析规则相应改为从字典选择菌门或菌属作为目标、只使用状态类条件，并输出「分析」「建议」两个自由文案字段加风险级别（低 / 中 / 高 / 仅提示），「仅提示」只出分析、不出建议、不配商品。逐份报告的正式分析运行仍在报告工作台内完成（ADR-0026），「分析规则」页面只保留只读的按菌门规则测试。规则目标层级、商品在小程序中的位置以及管理端商品配置是否并入菌门卡片仍待甲方确认（见 docs/product-design/open-questions.md「分析规则的目标层级」「商品推荐的用户端呈现」）。

本决策取代 ADR-0014：不再按“检测项主结论 + 合并兼容补充”的方式组合三类文案，而是在菌门分析单元内按风险与优先级排序、逐段原样形成分析与建议两个草稿。同时取代 ADR-0005：商品不再通过正文中的推荐位编码插入，而是作为菌门分析单元的商品推荐项出现。部分取代 ADR-0029：其“运营人工选择、不使用推荐引擎、商品配置与专业版本分开”的原则继续有效，但商品的挂载点由“单份报告的健康建议后”改为菌门分析单元。部分取代 ADR-0006：报告详情仍一次返回全部商品解析结果并批量查询商城，但按菌门而非推荐位编码组织。ADR-0020 的原则不变，菌群科普模板的字段按设计稿保留，只是把按检测状态切换的提示合并为一句固定提示。

## Consequences

- 报告工作台模块调整为来源与归属 / 检测结果 / 综合评定 / 分析与建议 / 商品推荐 / 发布检查 / 版本与记录；分析与建议按菌门卡片展示与编辑，每个菌门单独确认，商品推荐按菌门列出建议摘要与商品槽。
- 发布检查把“存在未确认的菌门分析单元”和“依据变化后未重新分析”列为阻断项；无命中的菌门允许单元为空。
- 小程序菌门详情页的「分析」「总体建议」tab 读取该菌门分析单元确认后的文案，建议 tab 下展示该菌门主推商品卡（临时口径）。
- 规则不再有绝对数值比较条件；`vs AVG notice` 为 `-` 的记录仍为有效结果，实验室比较状态记为「未标注」，只是不触发依赖 `high` / `low` 的规则。
- 删除报告级「整体分析解释」「总体建议」「分析整体确认」概念及其原型页面与 Mock 数据；删除健康需求标签与标签商品映射数据。
