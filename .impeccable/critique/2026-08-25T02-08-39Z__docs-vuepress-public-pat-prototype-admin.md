## Design Specificity Verdict

内容层面针对宠物肠道菌群检测，交互和业务控制层仍是通用 CRUD 后台套壳。门/属指标、品种正常区间、健康评级、规则测试和报告详情具有明确领域性；但生成、质控、复核、发布、撤回、更正与报告领取都没有专属流程。更准确的定位是“领域名词丰富的概念演示”，而不是已经成立的宠物检测运营后台。

自动 detector 以退化正则模式发现 11 条 warning：`side-tab` 5、`ai-color-palette` 2、`gray-on-color` 3、`broken-image` 1。其中 tooltip 边框、注释内 dashboard、模板三元 class 等大多是误报；有意义的旁证主要是通用色板、侧边强调和隐藏空图片。机械扫描没有推翻业务评估，真正的问题来自模块断链和业务控制缺失。

浏览器可视化未形成可靠证据：没有原生 Browser/[Human] tab，本机 Chrome headless 在页面和 `about:blank` 都因 macOS renderer/CVDisplayLink 问题退出 134。因此未声称存在用户可见 overlay，视觉判断主要使用成功打开的一页和源码证据。

## Overall Impression

原型已经能讲“配置驱动宠物报告”的售前故事：字典、正常范围、健康分级、分析规则、客户、宠物、报告都被显式建模。最大机会不是补更多 CRUD，而是把核心对象从“一张可随意编辑的报告”改成“可溯源的检测事实 + 版本化解释 + 经审核发布的报告”。

当前源码表达的链路是：

```text
字典/范围/等级/规则配置
→ 客户和宠物建档
→ 在报告里手填样本、检测值、状态、评级与建议
→ 保存可变 Report
→ 查看时用另一份硬编码范围/规则临时解释
→ 导出仍是占位
```

落地所需链路应当是：

```text
检测订单/报告认领
→ 样本登记与流转
→ 实验室结果导入
→ 完整性与 QC 校验
→ 按已发布配置版本生成解释
→ 专业审核/驳回
→ 冻结报告版本并发布
→ 小程序通知、查看、分享
→ 撤回/更正/复检闭环
```

## What's Working

1. 领域拆分方向是对的，已经意识到报告不是纯手写文案，而要依赖品种、参考范围、健康等级和分析规则。
2. 宠物可关联主人并带出档案，宠物侧还出现所有权历史概念，档案复用意图清楚。
3. 规则支持 AND/OR、多条件和历史报告测试，报告能显示匹配条件、分析与建议，具备可解释性雏形。

## Priority Issues

### [P0] 报告没有生成—审核—发布状态机

- **Why it matters**：当前 `pending / processing / completed / reviewed` 可被同一个人任意选择，已审核报告仍可编辑、评级、永久删除。小程序用户最终看到哪一版、由谁审核、何时发布都无法证明。
- **Fix**：把样本、检测、报告拆开管理；报告采用 `待生成 → 待审核 → 驳回/已批准 → 已发布 → 已撤回/已更正`。发布后冻结宠物/主人快照、原始结果、配置版本、审核人和生成时间，只能撤回或生成 v2，不能静默覆盖。
- **Suggested command**：`$impeccable shape`

### [P1] 检测数据没有来源、质控和溯源

- **Why it matters**：现在只有样本类型和检测日期，25+ 指标可手工输入；没有样本条码、采集/接收、实验室批次、检测方法、原始文件、上传人、QC 结果和重复样本门禁。系统无法判断数据是否属于这只宠物、是否完整可靠。
- **Fix**：新增 `Sample / LabRun / RawResult / NormalizedResult / QCResult`；导入先暂存并显示逐行错误、重复样本、缺失指标和 QC 结果。原始结果只追加不覆盖，人工修订记录前后值、原因、人员与时间；QC 未通过禁止生成和审核。
- **Suggested command**：`$impeccable harden`

### [P1] 配置中心是多套互相冲突的事实源

- **Why it matters**：字典、正常范围、RangeMatcher、报告和规则各自硬编码品种、指标、区间与健康等级；配置页修改不会稳定驱动最终报告。同一检测值可能在不同页面得到不同结论，历史报告也会随解释逻辑变化而漂移。
- **Fix**：建立版本化的 `MetricDefinition / ReferenceRangeVersion / HealthBandVersion / AnalysisRuleVersion`。规则只能选择指标 ID，明确精确品种、物种通用、全局默认的优先级，并带样本类型、方法、生效期。配置走草稿、影响测试、审批、发布、停用；报告冻结当时版本。
- **Suggested command**：`$impeccable shape`

### [P1] 角色权限、职责分离、隐私与分享边界缺失

- **Why it matters**：唯一身份是“管理员”，所有人可维护规则、录数据、评级、审核、删除；手机号联想暴露微信资料，报告显示电话和地址。规则制定者、录入员、审核者和发布者没有 maker-checker，隐私和专业责任链均断裂。
- **Fix**：至少拆实验室导入员、数据运营、规则专家、专业审核员、发布员、客服、审计员；实施菜单/字段/动作级权限和审计。PII 默认脱敏，小程序报告只对合法关系人开放；分享链接有有效期、撤销、下载控制、水印和访问记录。
- **Suggested command**：`$impeccable harden`

### [P1] 客户—宠物—报告关系不足以支持领取、共养、转让与去重

- **Why it matters**：宠物只有一个 `currentOwnerId`，报告又允许完全手输宠物和主人，形成游离文本快照。现实中的监护人、送检人、付款人、报告接收人可能不同；宠物转让、家庭共养、重复建档和错绑后没有安全处理方式。
- **Fix**：使用带角色和有效期的 `CustomerPetRelationship`；宠物有稳定 ID，可选芯片号/机构档案号。手输内容创建“待合并临时档案”。定义报告领取规则：订单/样本码 + 登录账号 + 手机验证或机构授权；已有报告的档案只停用/匿名化，不物理删除。
- **Suggested command**：`$impeccable onboard`

## Cognitive Load

8 项中失败 6 项，属高认知负荷。Grouping 基本通过，Visual hierarchy 勉强通过；Single focus、Chunking、One thing at a time、Minimal choices、Working memory、Progressive disclosure 失败。新增报告一次要求处理档案关联、主人、样本、状态、25+ 指标、健康评级和建议；规则又依赖自由文本指标。流程应按“来源确认 → 数据校验 → 生成解释 → 审核 → 发布”分阶段，并按角色和状态只展示当前可执行动作。

## Persona Red Flags

### Alex（高频运营人员）

- 七个平铺菜单间来回切换，没有待办队列、最近项、批量审核或键盘路径。
- 5 个门、20+ 属和 3 个统计指标逐项录入，批量导入最终只是“开发中”。
- 没有保存草稿、异常项优先、复制上次检测、查看配置变更影响等高频能力。

### Sam（键盘/屏幕阅读器用户）

- 模态框没有 dialog 语义、焦点陷阱、Esc 关闭和返回焦点；图标关闭按钮缺少可访问名称。
- 动态页面加载、保存、评级和筛选没有 live region；焦点不会转到新视图标题或首个错误。
- 固定 200px 侧栏没有窄屏/放大折叠方案。

### Riley（边界与审计压力测试）

- 零指标报告也可设为已审核，已审核报告还能改值、评级和删除。
- 百分比无总量一致性、单位、重复样本和重复报告校验。
- 改范围或规则后，历史报告查看结论可能漂移；删除后按数组长度生成编号还可能复用编号。

## Minor Observations

- 小程序端目前仍是“欢迎来到小程序 / 功能一 / 功能二 / 我的订单”的通用占位，没有报告列表、认领、检测进度、报告详情、分享、撤回通知或复检入口；核心价值时刻尚未设计。
- 健康等级筛选中“全部”和“未评级”都是空值，无法区分。
- 报告概览无论实际样本类型都显示“粪便样本”。
- 健康分级范围是自由文本，没有重叠、缺口和边界校验；报告等级与分数也可不一致。
- 规则指标允许自由文本，拼写错误保存时不会被阻止；多条规则同时命中也没有优先级、互斥和冲突处理。
- “有益/有害/中性”与饮食/益生菌建议带有专业健康含义，需由领域专家确认依据、证据等级、禁忌与免责声明；本次仅审查产品模型，不确认这些科学结论本身。
- 自动 detector 的 11 条 warning 大多是模板上下文误报，视觉问题优先级低于业务闭环。

## Questions to Consider

1. 这次售前要卖的是哪一段价值：仅“数字报告交付”，还是“检测订单—样本—实验室—报告—复检”的完整服务？
2. 谁对最终健康解释负责：完全自动、运营复核，还是专业人员审核后发布？
3. 历史报告遇到规则更新时应保持原结论，还是生成新解释版本并通知用户？
4. 宠物转让或家庭共养时，旧主人、新主人和报告接收人分别拥有什么查看与分享权限？
