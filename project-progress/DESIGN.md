# 项目进度管理 · 设计记录（实际成品）

seed 2fc4dc8e · grounded direction rank 1 · 工程总控墙

本文件描述 `project-progress/` 当前实际实现的视觉与信息系统，而非设计意图。
验收截图（provenance）：`.impeccable/review/project-progress/desktop.png`（1440×1100 首屏）、`.impeccable/review/project-progress/entry.png`（原型入口第三按钮）。

## 定位

面向甲方阅读的桌面大屏"工程总控墙"：把开发工作量、相对周排期、人工进度和会阻塞研发的甲方前置事项放在同一视野。不是内部项目管理工具，不做编辑、筛选、搜索、移动适配、打印或 PDF。

## 视觉系统（成品）

- **底色**：冷灰墙面 `#f4f5f6`，面板 `#fbfcfc`。无渐变、无玻璃、无阴影堆叠、无 hero。
- **线条**：石墨细线承担全部结构。面板外框 `1px #3a424a`，分隔线 `1px #c9ced3`。总控板周格线 1px，缓冲区周格线为虚线。
- **颜色纪律**：
  - 低饱和绿（填充 `#79a188`、文字 `#4e7a5e`）只表示研发进度与已完成状态。
  - 琥珀（文字 `#9a670e` / `#7d5208`、底 `#f6ecd9`）只用于待配合事项：顶部提醒条带、甲方筹备泳道图钉与文字、清单中的"未完成"状态签。研发区域不出现琥珀。
  - 状态不只靠颜色：进行中=绿色填充比例，已完成=实心绿+文字"已完成"，未开始=石墨描边，等待外部条件=虚线描边+文字"等待外部条件"，缓冲区=虚线区+标尺"20% 缓冲"标注。
- **字体**：系统中文字体栈（PingFang SC / Hiragino Sans GB / Microsoft YaHei / Noto Sans CJK SC），数字统一 `font-variant-numeric: tabular-nums`。无外部字体、无图标字体、无 emoji / Unicode 图标（图钉、箭头均为 CSS 绘制）。
- **动效**：仅任务明细展开/收起一处过渡（grid-template-rows 240ms），`prefers-reduced-motion` 下全部关闭。内容默认可见，无入场动画。
- **可访问性**：展开/收起为语义化 `<button>` 并同步 `aria-expanded`；`:focus-visible` 绿色 2px 焦点环；自定义选择色（石墨底白字）与细滚动条；正文对比度 ≥ 4.5:1。

## 版面结构（自上而下）

1. **顶栏**：标题"项目进度管理"、一句话说明、最后更新时间（HEAD 请求 `data.js` 的 `Last-Modified`，失败回退 `document.lastModified`，中文格式化）、返回原型入口链接。
2. **总控数据带**：一条带细分隔线的连续数据板——基础工作量 80 人日 / 人力缓冲 16 人日（20%）/ 合计 96 人日 / 总体进度（附绿色进度轨）/ 进行中任务 / 未完成待配合。数字全部由 `data.js` 实时计算。
3. **待配合条带**：琥珀底细边条，仅列未完成项与期望周次；全部完成时转为绿色提示。
4. **周次排期总控板**：第 1–11 周标尺（第 10–11 周为虚线 20% 缓冲区），左侧 292px 固定信息列（sticky），周列固定 86px，整板约 1238px，超出时仅板内横向滚动，页面无横向溢出。五条工作线：产品（1 行）、前端（13 行，含 PC 管理端 / 小程序组标签）、后端（9 行）、部署（6 行）、甲方筹备（7 行里程碑图钉）。板下注明 H5 兜底策略。
5. **任务明细**：按状态分组（进行中、等待外部条件默认展开；未开始、已完成默认收起），表格仅含任务、预计人日、人工进度三列。
6. **待配合事项完整清单**：事项 / 责任角色 / 期望周次 / 状态 / 受影响任务，纯展示不可点击。
7. **范围待确认**：5 项编号列表，仅展示不统计，注明"确认后重新评估并更新当前计划"。
8. **排期说明页脚**：人员配置、前后端并行与 Mock、5 日工作周、8 小时/人日、20% 缓冲独立计算、范围待确认不统计。

## 数据与计算

- 唯一数据源 `data.js`：29 条研发任务（80 人日：产品设计 4 / PC 管理端 22 / 小程序 12 / 后端 30 / 部署 12）、7 条甲方前置事项、5 条范围待确认。
- 缓冲率 20% 单独计算（80 × 20% = 16 人日，第 10–11 周虚线区），不摊入任何任务。
- 分类与总体进度均为研发任务 `progress` 的简单平均；`progress = 100` 自动视为已完成；前置事项与范围待确认不参与任何统计。
- 维护方式：只改 `data.js` 中任务的 `progress / status / startWeek / endWeek` 与前置事项的 `status / expectedWeek`。

## 已知取舍

- 周列固定像素（86px），1240px 以下视口由总控板内部横向滚动承接，左列 sticky 保持可读；不做响应式重排。
- 不绘制任务依赖箭头（`dependencyIds` 仅存于数据），不计算或推演延期。
- 初始总体进度 3%（仅"产品设计"100%），属真实初始状态而非占位美化。
